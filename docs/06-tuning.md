# 音質・遅延の調整ガイド（Phase 2）

企画書 4.2 の「調整する項目」を、実際の操作順に落としたもの。

**鉄則: 一度に 1 項目だけ変える。** 変えたら必ずプロファイルと [04-verification.md](04-verification.md) の試行表に記録する。

---

## 1. 調整の順序

```
① 入力音量      … マイクゲイン / GAIN in
② AUDIO 方式    … server / client
③ CHUNK         … 音切れと遅延のトレードオフ
④ EXTRA         … 声質と処理時間のトレードオフ
⑤ F0 Det        … ピッチ抽出方式
⑥ TUNE          … 声の高さ
⑦ INDEX         … モデルへの寄せ具合
⑧ S. Thresh     … ノイズゲート
⑨ GAIN out / vol … 最終音量
```

①②を飛ばして③以降をいじると、原因を切り分けられなくなる。

## 2. 各パラメータ

### GAIN in（入力音量）

- 小声が変換されない → 上げる
- 大声で割れる → 下げる
- Windows の「マイクブースト」も併せて確認する（上げすぎると割れる）

**目安**: 通常発話でメーターが 6〜7 割、大声でも振り切れない。

### AUDIO 方式

| 方式 | 遅延 | 安定性 | 使いどころ |
| :--- | :--- | :--- | :--- |
| `server` | 小さい | デバイス依存 | 本番向き。まずこれを試す |
| `client` | 大きい | ブラウザ依存 | `server` でデバイスを掴めない場合の代替 |

`server` で音が出ない場合は、他アプリがデバイスを占有していないか確認する。

### CHUNK

一度に変換する長さ。**音切れ対策の第一候補。**

| CHUNK | buf | 音切れ | 用途 |
| :--- | :--- | :--- | :--- |
| 128 | 小 | 起きやすい | 低遅延重視 |
| 256 | ↓ | 改善 | バランス |
| 512 | ↓ | かなり改善 | 安定重視 |
| 1024 | 大 | 起きにくい | 余裕のない PC |

**PC 性能が足りない場合は 1024 まで上げる**（公式 FAQ の推奨）。

### EXTRA

入力に含める過去音声の長さ。長いほど変換品質が上がるが、計算量が増える（おおむね長さの 2 乗で増加）。

| EXTRA | 声質 | res（処理時間） |
| :--- | :--- | :--- |
| 2048 | 粗い | 短い |
| 4096 | 中 | 中 |
| 8192 | 良い | 長い |

`buf < res` になる場合は EXTRA を下げる。

### F0 Det（ピッチ抽出）

| 方式 | 実行 | 速度 | 精度 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| `dio` | CPU | 速い | 低い | 負荷に余裕がないとき |
| `harvest` | CPU | 遅い | 高い | CPU で品質重視 |
| `crepe` | GPU | 速い | 高い | NVIDIA 向き |
| `rmvpe` | GPU | 速い | 高い | 初期候補 |
| `crepe full` / `crepe tiny` | ONNX | — | — | onnx 版向け |

**初期値は `rmvpe`。** 音切れするなら `dio` に落として切り分ける。

### TUNE（ピッチ）

**企画書 4.2 のとおり、`+9〜+14` などの固定値にしない。** 演者とモデルの組み合わせで試聴して決める。

| 変換 | 目安 |
| :--- | :--- |
| 男声 → 女声 | +12 |
| 女声 → 男声 | -12 |
| 同程度 | 0 |

数値を変えれば必ずキャラクター性が高まるわけではない。**不自然な高音化・低音化が起きたら戻す。**

### INDEX（RVC のみ）

学習時の特徴量に寄せる比率。0 = HuBERT の出力そのまま、1 = 元の特徴量にすべて寄せる。

- index が登録されているモデルのみ有効
- 0 より大きいと検索に時間がかかり、音切れの原因になることがある
- 0.3〜0.5 あたりから試す

**音切れが増えたら INDEX を下げる**（または 0 にする）。

### S. Thresh（ノイズゲート）

この値より小さい音量では変換せず無音を返す。小さいほど敏感。

| 症状 | 対処 |
| :--- | :--- |
| 小声が変換されない | 下げる（-60 → -50 → -40 の方向） |
| 無音時にノイズが乗る | 上げる |

### GAIN out / vol

最終音量。**ヘッドホンで聴いて決める。** 会場 PA の音量設計は本企画の対象外。

## 3. `buf` と `res` の見方

| 表示 | 意味 | 目標 |
| :--- | :--- | :--- |
| `buf` | 音声を切り取る 1 区間の長さ（ms） | **res より大きいこと** |
| `res` | 変換にかかる時間（ms） | buf より小さいこと |

```
buf > res  … 変換が間に合う（安定）
buf < res  … 変換が追いつかず音切れする
```

調整後は必ず実測値を `config/profiles/*.json` の `measured.bufMs` / `measured.resMs` に記録する。

> `server` デバイスモードでは `buf` が表示されない場合がある。その場合は `CHUNK` の表示値を目安にする。

## 4. 試行の記録

```markdown
| 試行 | 変更 | 値 | buf/res | 結果 | 採用 |
| :-- | :--- | :--- | :--- | :--- | :-- |
| 1 | 初期値 | CHUNK=128 EXTRA=8192 rmvpe | 320/280 | 時々音切れ | - |
| 2 | CHUNK を上げる | CHUNK=256 | 480/280 | 音切れ減 | ○ |
```

## 5. やってはいけないこと

- **複数項目を同時に変える** — 何が効いたか分からなくなる
- **数値だけを他人の環境からコピーする** — PC 性能・マイク・演者が違えば最適値も違う
- **`TUNE` を固定値で決め打ちする** — 必ず耳で決める
- **音切れを「PC が悪い」で片付ける** — まず `buf > res` を確認する
- **測定値を残さない** — 再現できなくなり、企画書 7 章のリスク「特定部員しか再現できない」に直結する
