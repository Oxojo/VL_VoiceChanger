# 開始直後の過負荷停止への対策

ユーザーから、ONNX CUDA 試験で最初の出力前に「入力に追いつかない」で停止する報告があった。
このメッセージは未返却入力が2秒分を超えた場合に出る。
従来はモデルをロードした時点でマイクを開始し、最初の推論の初期化時間も入力待ちを増やしていた。
実機の診断ログは未取得であり、報告された停止が初期化によるものかは未確定。

マイク開始前に、最初の区間と左contextを含む継続区間の代表的な入力長で推論するよう修正した。
長さが同一の場合は1回だけ実行。context > hop の場合でも、多数の中間区間を推論せず、代表2形状を直接準備する。
使い捨ての StreamingChunkedConverter でモデル出力長も検証し、音声・フレーム・統計を実セッションへ混ぜない。
準備が完了してから ready を返し、ブラウザがマイクを開始する。
準備時間は画面に別表示し、debug JSON の settings.warmup_ms に保存する。
API の warmup は既定 true。false は切り分け用。

開始までの準備時間は増えるが、初期化中のマイク入力を溜めない。
700 ms の入力蓄積設定や入力待ち2秒の上限は変更しない。
継続的に推論が遅い場合、未準備の入力形状や実行環境の問題がある場合は、引き続き停止する可能性がある。
この対策はすべてのCUDA形状・演算の初期化が完了することや実時間性能を保証しない。

検証:

- Python 全100件: 成功99・モデル不足によるスキップ1・失敗0。
- Chromium 全12件成功。最初の推論だけ2.3秒かかる模擬変換器で、
  その間マイクを開かず、準備後に再生できることを確認。
- 常に遅い模擬変換器では、準備後も従来どおり過負荷停止することを確認。
- 代表形状のサンプル長、warmup後の統計・debug要求番号の初期化、
  warmup中の不正な出力がready前に拒否されることを確認。

ログは logs/warmup-tests.log と logs/warmup-browser.log（Git管理外）。
実RVC/ONNXモデルとGPUがないため、ユーザー実機での解消と速度は未確認。
同じ停止が続く場合は debug を有効にし、エラー停止後の診断JSONで追加調査する。
