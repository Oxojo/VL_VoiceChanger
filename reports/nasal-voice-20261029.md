# 鼻詰まり感の確認と合成器の互換性修正

## 提供音声の計測

同じ長さ（1.74 秒）の入力 WAV と出力 WAV を受領。録音本体は Git 管理外。
聴感上の「鼻詰まり」は以下の数値だけで判定できず、最終判断は本人の試聴が必要。

| 指標 | 入力 | 提供された出力 |
| :--- | ---: | ---: |
| サンプリングレート | 16 kHz | 40 kHz |
| ピーク絶対値 | 1.000 | 0.673 |
| RMS | 0.1830 | 0.1673 |
| F0 中央値（RMVPE） | 119.38 Hz | 238.37 Hz |
| 0〜300 Hz のパワー比率 | 34.86 % | 80.57 % |
| 300〜800 Hz のパワー比率 | 60.45 % | 15.48 % |

帯域比率は Welch 法・窓長 1024 で全体を集計したもの。
F0 がほぼ 2 倍なので +12 半音相当の変換と整合するが、設定値そのものは未確認。
声質変換・ピッチ変更でパワー分布は変わるため、低域比率の増加だけを異常や鼻声と断定しない。

入力には `abs(x) >= 0.999` が 17 サンプルあり、振幅限界に達している。
録音段階の飽和の可能性があるので、次の録音では入力ゲインを少し下げて比較する。
保存済み録音を後から小さくしても、失われた波形は元に戻らない。

## 実装で確認できた不一致

`engine/model/synthesizer.py` の GeneratorNSF 最終段の LeakyReLU が 0.1 だった。
参照実装はアップサンプル段では 0.1、最後の `conv_post` の直前のみ既定の 0.01 を使う。
学習済み重みと演算の対応を保つため、最終段だけ 0.01 に修正。
EQ やフォルマント補正を追加したものではない。

参照:
https://github.com/w-okada/voice-changer/blob/master/server/voice_changer/RVC/inferencer/rvc_models/infer_pack/models.py

## 比較ファイル

手元のつくよみちゃん通常1、話者 0、+12 半音、一括、ノイズ除去・ハム除去なし、seed 1234、
CUDA で同一入力を修正前後に変換。提供された出力のモデル・設定が同じかは未確認。

- 修正前: `logs/verify/nasal-before.wav`
- 修正後: `logs/verify/nasal-after.wav`

ともに 1.74 秒・40 kHz、クリップなし。
RMS は 0.1664 → 0.1655、F0 中央値は 238.37 → 238.51 Hz。
全体の帯域分布の変化は小さく、この修正だけで鼻詰まり感が解消するとは確認できていない。
全 58 テスト成功。最終活性化の係数を確認する回帰テストを追加。

## 続けて確認すること

- 使用モデル、ピッチ、ノイズ除去の強さ、一括／分割の設定を確認する。
- 入力ゲインを下げ、マイクや OS の強い音声加工を切った新しい録音で比較する。
- 同じ条件で別モデルも比較し、モデル固有の声質かを切り分ける。
- 母音・子音を含むもう少し長い発話で、鼻詰まり感が出る箇所を本人が確認する。
